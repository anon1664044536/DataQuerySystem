## 智能问数系统开发日志

### 0.0.1

**系统初始化与可行性预研**

*   **技术栈构建**：搭建基于 Java + Spring Boot + DashScope (通义千问) 的语义解析基础框架。
*   **MQL 定义**：制定了基于 JSON 的中间表示协议 (MQL)，用于解耦自然语言意图与物理 SQL 语法。
*   **对比实验**：实现了与 NatSQL 的对照性研究脚本，验证了在复杂嵌套查询下使用中间表示层的架构优势。

### 0.0.2

**电力行业领域知识库与基准建设**

*   **数据集构建**：针对 PMS (电力管理系统)业务场景，手动构造了覆盖资产、备件、项目、组织架构四大领域的 100 道高质量题目（Questions + Golden SQL）。
*   **评测基座**：开发了 `DatasetEvaluator` 评测引擎及 `ReferenceBuilder` 基准答案生成工具。
*   **原型验证**：完成了第一版基于双阶段 (NL2MQL -> MQL2SQL) 的原型机开发，建立了 Execution Accuracy 的自动化度量体系。

### 0.1.0

**第一版生产级语义解析流水线 (PMS 专用版)**

本次更新完成了从“原型机”向“工业级”管线的深度演进，重点解决了微服务异构数据库环境下的逻辑幻觉与库表寻址问题。

#### 1. 架构升级：引入三阶段解析管线
*   **NL2MQL (IR 提取)**：由直接生成 SQL 转为生成中间表示 (JSON)，锁定业务意图。
*   **Schema Linker (子结构裁剪)**：[新增] 根据 MQL 实时提取核心 DDL 结构。强制注入 `USE <database>;` 指令，彻底解决了多库环境下“表不存在”的报错。
*   **MQL2SQL (精准生成)**：[优化] 将原始问题、MQL 以及 Schema Linker 裁剪出的 DDL 三方加权，生成最终 SQL。

#### 2. “零幻觉”安全加固
*   **精准前缀法则**：强制要求模型根据注入的 `USE` 指令补全表前缀（如 `middleground_ast.xxx`），禁止随意猜测 `pms.` 前缀。
*   **被动关联防御**：严禁模型在 DDL 缺失外键的情况下盲目 JOIN 机构表，杜绝了无中生有的虚假关联。
*   **自动过滤丢弃**：模型现在能识别 DDL 缺失列，并自动丢弃 MQL 中无效的 `filters`（如时间列缺失），不再生成 `1=0` 这种逻辑死锁 SQL。

### 0.2.0 (当前版本)

**多智能体架构深度治理与工程健壮性增强**

本次更新聚焦于系统底层治理，实现了从“功能实现”向“高可靠架构”的跨越，全面对齐学术论文技术指标。

#### 1. 意图边界校验：MQL 抽象语法树 (AST) 过滤
*   **MqlValidator**：[新增] 在 Java 后端引入强类型校验逻辑。在 MQL 进入下一阶段前，对其 JSON 结构进行深度扫描。
*   **异常阻断机制**：自动拦截 `query_type` 缺失、`metrics` 为空或“趋势查询”缺失时间维度等语义崩溃案例，实现毫秒级错误反馈。

#### 2. 高并发工程化：评测引擎性能飞跃
*   **并行调度模型**：[重构] `SpiderEvaluator` 全面接入 `ThreadPoolExecutor` 并发框架，将核心线程数设定为 8。
*   **性能提升**：在 1034 条 Spider 验证集上的总评测耗时缩短了约 70%，并有效通过线程池拒绝策略实现了对外部 API 的流量削峰。

#### 3. 运行态全链路审计：基于 Spring AOP 的无侵入监控
*   **MetricAspect**：[新增] 利用面向切面编程技术，实现对 `AskingAgent` 网络请求的透明化拦截。
*   **量化分析基座**：系统现可自动统计单次查询中各个 Agent 节点的端到端时延（Latency）与 Token 消耗，为消融实验提供了最为精准的数据支撑。

#### 4. “值幻觉”终结者：真实数据探针注入
*   **SchemaDataInjector**：[核心] 引入动态数据样例注入机制。在 SQL 编译前，系统自动嗅探物理数据库中相关表的真实 Top-3 数据行。
*   **语义对齐**：通过将真实数据挂载至 DDL 注释中，大模型得以精准识别业务枚举值（如 `'1'` 代表 `'运行中'`)，彻底消除了自然语言表述与底层存储值不一致导致的空结果集问题。

#### 5. 多维评测矩阵：NL2PY2SQL 科学基线
*   **Baseline 构建**：[新增] 实现了基于“Python 思维链”的 NL2PY2SQL 解析路线，作为主干 MQL 管线的学术对照组。
*   **复杂逻辑突破**：验证了在处理 Extra Hard 级别题目时，通过 Python 中间层理清聚合优先级的可行性，为系统的长远演进提供了量化依据。

#### 6. 文献与规范化
*   **学术标准对齐**：全系统参考文献库已按照 GB/T 7714-2015 国家标准完成规范化校对。
*   **方言容错增强**：优化了 MQL2SQL 编译器针对 SQLite 与 MySQL 不同方言下日期处理函数的动态适配逻辑。
